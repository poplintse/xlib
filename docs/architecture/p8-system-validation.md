# P8 System Validation

Status: complete

P8 verifies the P0–P7 architecture as a system. It does not add a Product Capability, change the sync contract, or authorize a release. Automated gates, local fault recovery, and physical-device performance automation are implemented. Real-device cross-client continuity, the iOS physical-device release chain, and distribution-channel enforcement were confirmed by the user on 2026-09-21. The iOS Release performance record passed its automated validator on 2026-09-23; Android physical-device performance remains explicitly waived for this P8 run.

## Release Gate

`make check-alpha` is the required local Alpha gate. It now:

- runs the tracked-sensitive-data scan, contract checks, release checks, Backend checks, AppleShared tests, Android tests/lint/build, and iOS unit/UI tests;
- always provisions an isolated PostgreSQL 17 cluster through `test-backend-postgres.sh`; an unavailable database is a gate failure, not a skipped success;
- runs iOS tests serially to avoid test-host collisions;
- snapshots Android, iOS, Backend, and selected release-manifest version sources before the whole run and fails if any check changes them.

CI and release verification use PostgreSQL 17 with a database owner and a separate restricted application role. Release verification also runs Android tests/lint and iOS unit/UI tests before producing unsigned debug artifacts. It does not sign, publish, tag, deploy, or upload to an app store.

The sensitive-data gate examines tracked files and reports only the file path and finding category. It rejects committed environment files, credential/signing material, private keys, common provider tokens, and credentialed database URLs that are not explicit test placeholders.

## Physical-device Performance Evidence

The fixed fixture set is generated by `make prepare-p8-performance` and identified by SHA-256 `a420769d87d32bf61c9e49d2e3267cf1c1bf5ef92e6e49747126a8d93192c797`. It contains 128 KiB and 32 MiB UTF-8, UTF-16LE, and GB18030 books plus twenty 256 KiB bulk-import books. Generated fixtures, raw `xcresult` bundles, and metric JSON remain under the ignored `artifacts/p8-performance/` directory.

`make test-p8-ios-device` runs the opt-in `XLibReaderP8` Release scheme against one connected, unlocked physical iPhone. The suite opens all twelve size/encoding/cold-or-cached combinations five times, turns thirty pages in each direction, searches beyond 200 results five times, verifies cancellation, imports twenty books five times, and performs five deterministic interrupted-state recovery runs. It exports the XCTest metrics and test tree, ingests them into the performance record, and runs the validator. The performance-only compile flag and isolated bulk-import roots keep the harness out of production behavior and the user's normal library. The interrupted case constructs the same `.importing` state left by termination, terminates the app between phases, then verifies restart cleanup and completion; it does not claim a deliberately injected process crash.

The current iPhone result is Release 0.11.0/build 45 on iPhone 15 Pro Max running iOS 26.5.2. The validated summary is:

| Area | Runs | Result |
|---|---:|---|
| Open book | 5 per each of 12 scenarios | median first-text-draw latency 77.9–102.9 ms; scenario peak physical memory 42.1–60.4 MB |
| Page forward/backward | 30 per direction | median accepted-turn-to-transition-completion latency 378.7/378.6 ms; p95 380.9/380.2 ms |
| Search beyond 200 | 5 | median first result 34.2 ms; completion 68.3 ms; peak physical memory 49.7 MB; cancellation passed |
| Bulk import, 20 books | 5 | median 86.5 ms; p95 94.4 ms; peak physical memory 26.8 MB; zero retained temporary files |
| Interrupted-state recovery | 5 | median 78.5 ms; p95 79.1 ms; peak physical memory 26.8 MB; recovery passed with zero retained temporary files |

Page-turn timing is an end-to-end interaction latency from an accepted turn through transition completion. It is not presented as CPU time. Search completion is recorded after automatic continuation reaches 400 matches in the performance build; production search behavior is unchanged.

The current XCTest `XCTStorageMetric` exposes process logical writes but no read-byte metric. The gate therefore requires five logical-write samples for every open scenario and does not fabricate read values from TXT size or requested buffers. Cold-open logical-write medians range from 389.1 to 430.1 kB except the small GB18030 scenario at 389.1 kB median/839.8 kB p95; cached-open medians range from 24.6 to 41.0 kB. Existing Activity Monitor disk-read samples for large UTF-8 remain marked exploratory and are not required by the automated gate. Future audits may add process read samples when Apple exposes a stable automated collector.

`make check-p8-performance-record` verifies fixture hashes, Release version/build and device identity, the explicit Android waiver, all iOS run counts, search cancellation, bulk recovery, and temporary-file cleanup. It writes median and nearest-rank p95 results to `artifacts/p8-performance/performance-results.md`. Android samples remain available for a future audit, but no Android performance value is claimed in this P8 run.

The user-confirmed continuity, release-chain, and distribution-floor checks do not include sanitized device or service logs. Their absence is recorded rather than filled with inferred details.

## Fault and Security Boundaries

- SQLite writes that fail for capacity reasons must not leave partial books, progress, bookmarks, TOC, settings, or sync state.
- Import interruption and file deletion use existing temporary-file and pending-deletion recovery paths.
- PostgreSQL rollback, capacity concurrency, upload/delete ordering, identity isolation, and revoked-device rejection remain mandatory.
- Logs may contain event type, result, duration, and short-lived diagnostic identifiers. They must not contain TXT content, email, Token, credential, local file path, or real service URL.
- TXT remains in the file system and credentials remain in Keystore/Keychain. P8 does not change the SQLite, Secure Store, or PostgreSQL boundaries.
