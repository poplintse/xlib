# XLib iOS 客户端实现说明

本文记录当前代码的界面与运行方式，不是跨端需求。已确认产品规则见 [iOS 客户端能力](../product/clients/ios.md)；实现差距统一见 [CURRENT](../CURRENT.md)。

## 1. 范围与原则

- iOS 客户端位于 `apps/ios`，使用 Swift 6、SwiftUI、UIKit 与 Core Text；可由 Apple 平台复用且不含 UI 的代码位于 `packages/apple-shared`。
- 阅读、书架和本地进度完全可离线使用；同步服务尚未部署时，用户仍可填写并保存同步配置，不会阻塞本地阅读。
- 同步只传输阅读进度与同步所需的设备信息，不上传 TXT 正文、书架内容、书签、目录、搜索索引或阅读显示设置。
- 所有进度以原始 TXT 文件的**字节 offset**为准。字符编码或 Unicode 代理对不得改变已保存位置的含义。
- iOS 的真实后台执行时间受系统控制，不能承诺在后台每 20 秒持续运行；应用处于前台时才执行周期同步。

## 2. 阅读器

### 2.1 页面与文本排版

- 阅读正文画布左右各保留 **20 pt**：内容宽度为屏幕宽度减 40 pt。
- 正文段落采用 Core Text 的两端对齐；段落末行按系统排版规则保留自然宽度。
- 页面缓存、目录、搜索和进度恢复均使用字节 offset，避免 UTF-8/UTF-16 混用造成位置漂移。

### 2.2 触摸翻页

阅读画面按宽度分为三个区域：

| 区域 | 占比 | 动作 |
| --- | ---: | --- |
| 左侧 | 35% | 后翻（上一页） |
| 中间 | 20% | 打开/关闭阅读菜单 |
| 右侧 | 45% | 前翻（下一页） |

- 前翻和后翻请求按顺序串行处理，快速连续点击不会在一次动画中跳过多页。
- 翻页使用柔和的 3D 翻页效果，单页动画时长为 **0.36 秒**。动画结束后才切换到稳定页，避免末段先停顿、再跳至下一页的视觉问题。
- 开启“减少动态效果”时，翻页直接完成，不播放 3D 动画。

### 2.3 阅读进度

- 当前打开、翻页和退出路径会保存本地进度；尚需按产品定义区分位置恢复与正式阅读时间更新，不能将所有保存都视为新阅读事件。
- 正在阅读时，周期同步会强制上报当前页，即使进度自上次上报后没有变化；这样在进入后台前保持不变的阅读位置也能得到一次最新上传机会。

## 3. 阅读进度同步设置

入口为“阅读进度同步”。页面从上到下固定为：**状态**、**同步设置**、**同步设备管理**。

### 3.1 状态卡片

状态卡片始终显示，包含三项：

1. **同步状态**：未同步、已连接或网络/服务不可用，并显示最近一次错误信息（红色）或可用状态说明。
2. **最后同步时间**：尚未完成同步时显示为空状态，成功后显示本地记录的最近成功时间。
3. **同步刷新**：唯一的手动同步入口。

“同步刷新”的逻辑如下：

- 邮箱、当前设备和服务器地址尚未全部完成有效配置时，不发起网络请求，显示红字“请先完成同步配置”。
- 尚未建立同步会话时，使用当前本地配置启动同步。
- 已建立同步会话时，立即按当前配置刷新云端同步状态；本地阅读进度由同一套周期同步流程上传。
- 成功后更新状态和最后同步时间；设备列表在进入“同步设备管理”时加载。失败时保留可编辑配置并显示具体错误。

页面不再提供独立的“刷新状态”“同步服务器”“邮箱”“设备名称”或“云端数据”卡片，也不提供“关闭本机同步”入口。

### 3.2 同步设置卡片

同步设置卡片包含带右向箭头的三个独立配置项：

1. 邮箱
2. 当前设备
3. 服务器地址

点入后各自进入标准 iOS 设置页，只编辑一个值。配置页面不使用“保存”按钮：有效值在键盘完成、焦点离开输入框或离开页面时自动保存到本地；无效值保留在输入框并显示校验提示。

| 项目 | 规则 |
| --- | --- |
| 邮箱 | 必填，按邮箱格式校验；保存时规范化为小写。 |
| 当前设备 | 必填，最长 **20 个字符**；超出部分不能保存。 |
| 服务器地址 | 必填，必须是有效 HTTPS 地址。 |

修改三个配置中的任一项时：

- 配置值立即持久化在本机；即使服务端未部署，返回设置页后也必须显示已保存的值。
- 若用户曾成功启动过同步，则立即清除旧同步会话的 Token、云端缓存、同步状态、设备列表和最后同步时间，防止旧账号、设备或服务器的信息继续显示或被使用。
- 已启动同步的标记保留。应用前台的下一轮周期同步（或用户点“同步刷新”）会读取**最新本地配置**，重新建立会话并同步。

### 3.3 同步设备管理

- 卡片名称为“同步设备管理”，使用右向箭头进入详情页。
- 尚未同步时，详情页只显示本机设备。
- 同步成功后，详情页显示本机及服务器返回的其他设备；可移除远端设备。
- 移除设备的 DELETE 请求即使没有业务字段，也发送合法的空 JSON `{}`，避免声明 `application/json` 却无请求体而被服务端拒绝。

## 4. 自动同步与生命周期

同步只有一个应用前台定时任务，间隔为 **20 秒**；不存在“刷新云端状态”和“阅读进度上传”两套独立定时器。

前提是用户至少成功启动过一次同步，且三个本地配置项都有效。每一轮执行同一套流程：

1. 读取本地保存的邮箱、设备名称和服务器地址。
2. 若尚无有效会话，按这些最新配置建立同步会话；建立后由后续周期继续上传。
3. 若已有会话且正在阅读，上传当前书籍的当前进度，即使位置未变化。
4. 当前代码在无阅读会话时仍上传保存的书库进度；这是 Decision 0005 已否定的实现缺口，后续需移除，不能作为其他端的要求。
5. 成功后更新状态和最后同步时间；失败后显示错误，并等待下一轮或手动“同步刷新”重试。

应用进入后台时，定时器停止，并尽力立即上报当前阅读会话的一次进度。再次回到前台后恢复 20 秒定时器。由于 iOS 的后台调度限制，后台期间不会承诺持续的 20 秒同步。

应用启动或网络恢复后，协调器同样读取本地配置和本地凭据恢复状态；网络故障不会删除本地书籍或本地阅读位置。

## 5. 本地数据与安全边界

- 同步配置、启动标记、阅读位置和最近成功状态保存在本机；会话凭据使用系统安全存储。
- 变更账号、设备或服务器会撤销旧会话信息，但不会删除本地 TXT 文件和本地进度。
- 当前 Alpha 服务使用固定 Token 模型，认证强度有限；不得把它描述为面向高敏感账户的认证方案。详见 [`docs/API.md`](../API.md) 和 [`sync-server.md`](sync-server.md)。
- 日志和测试输出不得包含邮箱、Token、服务器凭据或完整书籍内容。

## 6. 开发、构建与验证

- 从仓库中的 `apps/ios/XLibReader.xcodeproj` 打开工程；不要打开旧 worktree 中遗留的工程副本。
- 常规构建和测试不得修改版本文件或 `Info.plist` 的版本号。
- 首选根目录的 `make check`；仅验证 iOS 时可运行工程的 Simulator 测试。测试覆盖 UTF-16/字节 offset 映射、分页、两端对齐、翻页排队、同步配置持久化、20 秒统一调度和设备移除请求体。
