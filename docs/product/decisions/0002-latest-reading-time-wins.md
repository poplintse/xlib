# Decision 0002：最近阅读时间优先，跳转前展示当前位置

状态：accepted，用户于 2026-09-14 明确确认。取代历史 D-007 的 offset 优先裁决；不修改其他尚未确认的业务策略。

## Context

历史文档要求保留最远阅读位置，当前后端主要按阅读时间裁决。用户需要跨设备接续最近一次阅读，包括主动回读。

## Decision

- 同一用户、同一 bookHash + fileSize 的候选进度，优先选择 readAtMs 更新的状态。offset 仍是精确位置真值，但不是状态新旧的裁决依据。
- 最近一次阅读可以覆盖更靠后的旧位置。例如上午读到 60%，下午回读到 30%，下午的进度成为云端最新状态。
- 阅读时间相同的确定性裁决沿用现行协议，不在本次增加“同时保存最远位置”的模型。
- 跳转必须经用户确认。每次提示跳转时，除目标进度外，必须明确展示“当前阅读进度 xx%”，取提示时当前书籍的本地正式阅读位置；不能以远端进度冒充当前位置。
- 百分比由原始 offset / fileSize × 100 派生，与阅读界面显示精度保持一致。展示信息不改变精确位置存储方式；控件和布局由各端决定。

示例提示内容：当前阅读进度 60.00%；其他设备最新阅读进度 30.00%；是否跳转？用户选择暂不跳转时不自动改变当前阅读页。

## Reason

用户明确选择最近阅读时间优先，并要求跳转提示增加当前位置，便于判断跳转前后的变化。

## Consequences

CAP-PROGRESS-SYNC 按本决定定义。旧同步文档内最远位置/offset 优先相关段落不再有效，历史 D-007 保留并标注被取代。Android 已补齐当前位置提示及时间生成测试，iOS 仍有实现缺口；后端现有时间优先方向不再属于该项产品冲突，但不据此宣称全链路验收通过。

实施与验收状态见 [CURRENT](../../CURRENT.md)。阅读时间更新动作及阅读前比较阶段已由 [Decision 0003](0003-pre-reading-progress-comparison.md) 明确；同步配置自动应用、空闲期上传范围等问题仍待逐项确认；本决定不授权将周期上传时间直接当作新的阅读时间。

同步配置生效策略现已由 [Decision 0004](0004-sync-configuration-auto-apply.md) 确认；先前提到的该项待决状态已结束，其他未决问题保持不变。

上传范围现已由 [Decision 0005](0005-sync-only-current-reading-book.md) 确认为仅当前正式阅读书籍；先前空闲期上传范围的待决状态结束。
