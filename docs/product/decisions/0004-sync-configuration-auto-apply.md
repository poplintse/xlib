# Decision 0004：首次手动开启，后续有效配置自动应用

状态：accepted，用户于 2026-09-14 确认。取代历史 D-008 的配置修改后必须手动应用规则。

## Context

Android 保存配置后暂停同步，等待手动刷新；iOS 在曾启动同步的情况下清除旧会话，并在后续前台同步周期按新配置建立会话。差异涉及实际连接与同步授权，不只是设置界面。

## Decision

- 首次开启同步必须由用户手动触发。仅填写或保存邮箱、设备名称和服务器地址，不代表首次开启同步。
- 已成功开启同步后，有效配置修改自动生效，无需再次点击同步刷新。保存有效值后，后续可执行的同步流程读取最新完整配置并自动建立新会话；不要求操作系统无法保证的即时后台执行。
- 任一有效配置实际改变时，旧会话立即失效：停止使用旧凭据，并清除旧会话凭据、云端缓存、设备列表、待处理跳转提示及旧同步状态。保留已开启标记、本地书籍和本地阅读进度。
- 不得将旧 Token 发送到新服务器，也不得让旧请求的延迟响应重新覆盖新会话状态。
- 无效输入不覆盖有效的已保存配置、不以无效值建立连接；新会话必须使用完整有效配置。
- 新会话建立后先拉取云端状态；当前书按 Decision 0003 完成阅读前/恢复比较和必要的提示、用户选择后，才允许上传本书进度。配置保存或会话建立不等于可以直接上传，也不刷新阅读时间。
- 手动同步刷新仍可用于主动启动或刷新，但不再是有效配置修改后的必经步骤。

## Reason

用户认可有效配置保存后自动应用，避免保存与生效分离；通过失效旧会话和先拉取比较，保持账号、服务器边界及阅读进度语义。

## Consequences

CAP-SYNC-IDENTITY 以本决定为准。Android 已补齐自动应用、最新配置排队合并和旧提示失效测试；iOS 已补齐会话失效、旧响应隔离及先比较再上传，并通过协调器回归测试。当前状态见能力矩阵，不以文档批准代替实现验收。
