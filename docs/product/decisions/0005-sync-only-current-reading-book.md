# Decision 0005：只上传正在阅读的书籍

状态：accepted，用户于 2026-09-14 明确确认。限定 Decision 0003 的联网恢复上传范围。

## Context

Android 周期上传依赖活动正式阅读会话，iOS 无阅读会话时也会上传保存的书库进度。用户明确只需要上传正在阅读的书籍，离线阅读结束后无需将其补传到其他设备。

## Decision

- 上传对象仅限当前正在正式阅读的书籍，且已完成必要的云端比较与用户选择。阅读前准备和搜索临时阅读不属于可上传会话。
- 没有活动正式阅读会话时，不遍历书库上传保存的进度，不因停留书架、修改同步配置或恢复网络而补传已结束会话的离线进度。
- 离线阅读期间照常保存本地位置和实际阅读时间。若联网恢复时仍在正式阅读该书，按 Decision 0003 先拉取比较、处理必要提示，再恢复本书上传。
- 若联网恢复时已经离开该书，本地进度保留，但不为其建立补传任务或历史上传队列。API 支持批量条目不代表客户端应全书库上传。
- 日后重新打开该书，使用当时保存的本地位置和时间，重新执行阅读前比较、选择和定位；进入新的正式阅读会话后才允许按当前规则同步。这不是永久禁止该书今后同步。
- 本决定限制上传范围，不禁止正常拉取云端状态；无活动阅读会话时的拉取不得触发离线进度补传。

## Reason

用户明确选择只同步正在阅读的书籍，不需要将离线阅读完毕的书籍进度同步到其他设备。

## Consequences

CAP-PROGRESS-SYNC 采用本规则。iOS 当前 syncStoredReadingProgress 的空闲期全书库上传不符合新定义，应在后续代码工作中移除该上传路径；不应为保留该路径继续扩展批量拆分或去重功能。Android 活动会话上传方向一致，但完整边界仍需验证。

实施与验收状态见 [CURRENT](../../CURRENT.md)。现有后台/退出提交不能被解释成允许在会话结束后持续补传；具体生命周期实现仍需在后续代码符合性检查中核对。

验收：离线从 20% 读到 25%，退出到书架后联网，只保存本地 25%，不上传该书；如果恢复网络时仍在阅读该书，先比较再允许上传；之后重新打开该书则重新执行阅读前流程。
