# Decision 0010：云端进度只按单本书删除

状态：accepted，用户于 2026-09-14 明确确认。将 CAP-CLOUD-DATA-CONTROL 从 candidate 提升为 active，并收窄为单本书的云端进度管理。

## Context

初始化时 DELETE /v1/progress 会删除当前身份下所有书籍的云端进度。用户明确要求只提供单本书的删除接口，不提供整个身份下全部书籍进度清空。

## Decision

- 产品仅提供删除指定单本书云端阅读进度的功能和接口，不提供清空当前身份全部书籍进度的功能或接口。
- 删除范围由当前已认证用户与该书的 bookHash + fileSize 唯一确定，不使用本地书籍 ID、书名或显示百分比定位服务端记录。
- 删除不得影响其他书籍的云端进度、同步身份、设备、本地 TXT、本地书签或本地阅读位置及时间。
- 不得用现有全量删除进度或删除身份接口模拟单书删除；缺少书籍身份时不能退化成全部删除。
- CAP-CLOUD-DATA-CONTROL 保留稳定 ID 和文件名，定义改为单书删除；作为 Shared Optional Capability，对提供同步的客户端成立，不强加给不支持同步的客户端。

### 删除后的上传暂停与恢复（用户已确认）

- 单书云端进度删除成功后，发起删除的客户端在本次阅读会话中暂停该书上传；继续翻页仍正常保存本地进度和实际阅读时间。
- 周期同步、手动同步刷新、网络恢复或同步会话重建不能在同一本书的本次阅读会话中绕过暂停。
- 退出该书并重新打开后，重新执行 Decision 0003 的阅读前比较、必要提示及定位；完成后，新的正式阅读会话才恢复正常同步。仅切后台再返回不等同于退出并重新打开书籍。
- 删除的是非当前阅读书籍时，该书本来就不应上传；下一次打开仍执行正常阅读前流程，不产生后台补传任务。
- 本规则暂停发起删除客户端的本次阅读会话，不代表永久禁用该书同步，也不代表已经实现其他设备会话的全局暂停。

## Reason

用户明确限定单书操作，避免一次操作清空其他书籍进度。已有明确产品确认，因此不再将单书删除能力标为 candidate。

## Consequences

当前后端与 OpenAPI 已实现 `DELETE /v1/progress/{bookHash}/{fileSize}`，旧全量进度删除及身份删除路由已移除；两端传输方法均要求完整书籍身份。具体参数、204 幂等语义及错误见 [API](../../API.md)。未执行实际用户数据删除，也未部署。

Android 已补齐用户入口、在途上传与删除的串行顺序以及本次阅读会话暂停/重开恢复，包含协调器测试；iOS 也已补齐对应入口、串行删除、阅读会话暂停及重开恢复，并通过协调器回归测试。0.11.0 指定双端真机接续中的单书云端进度删除已由用户确认通过；服务端 PostgreSQL 集成测试覆盖范围限定与并发，未提供真机逐项日志。服务端删除不会永久阻止其他设备后续合法上传。

验收需覆盖：只删除目标书，不影响同哈希不同大小或其他书籍、其他身份、设备和本地数据；无效标识不能扩大删除范围；删除后本次会话不上传，手动刷新及网络恢复不解除暂停，退出重开并比较后恢复。测试结果及剩余缺口见 [CURRENT](../../CURRENT.md)。
