# Decision 0013：搜索到书末后由用户选择从开头继续

状态：accepted，用户于 2026-09-14 明确确认。

## Context

搜索默认从当前阅读位置向后进行。Android 已在到达文件末尾后提供从开头继续的入口，iOS 未提供；因此前半本书是否可被同次查询覆盖存在差异。

## Decision

- 启动搜索时记录该次搜索的原始起点，先向后搜索至书末；分批继续加载遵守 Decision 0012。
- 到达书末且原起点不在书首时，提示用户选择是否从书籍开头继续；未经用户选择，不自动回绕。
- 用户选择继续后，使用同一关键词从书首向后搜索，到原起点即结束，不再次搜索原起点到书末的部分，不自动循环。
- 原起点固定为本次搜索启动时的位置，不因临时阅读结果而改变。回绕不改变正式阅读进度，也不生成正式阅读时间。
- 从书首开始的搜索到达书末后直接结束，无需再次提供回绕；不继续时保留已有搜索结果。
- 回绕前后的结果均遵守不区分大小写、不重叠命中和每批最多 200 条的规则；操作入口由客户端设计。

## Reason

用户认可先查找当前位置之后的内容，再自主决定是否查找前面的内容，避免自动循环和重复搜索。

## Consequences

CAP-SEARCH 采用本规则。Android 已覆盖手动回绕至固定原起点及分批搜索组合；iOS 需补齐回绕选择及搜索范围控制。当前状态见能力矩阵，关键词长度计数由 [Decision 0014](0014-search-query-character-count.md) 确认。

后续验收覆盖中途起搜后到末尾、用户不继续、用户选择继续并在原起点结束、从书首起搜、无结果和跨批次续查。实施与验收状态见 [CURRENT](../../CURRENT.md)。
